# 141. 环形链表

题目链接：https://leetcode.cn/problems/linked-list-cycle/

难度：Easy

标签：链表、哈希表、快慢指针

## 题目内容

给定一个单链表的头节点，判断链表中是否存在环。

如果某个节点的 `next` 指针指向了前面已经出现过的节点，那么链表就会形成环。

## 哈希表思路

第一种比较容易想到的方法是用集合记录走过的节点。

遍历链表时，每经过一个节点，就判断它之前有没有出现过：

- 如果这个节点已经在集合里，说明链表有环。
- 如果走到空节点，说明链表没有环。

这个方法很好理解，因为有环的本质就是：

```text
遍历时又回到了已经走过的节点。
```

哈希表方法的缺点是需要额外空间保存节点。

## 为什么会想到快慢指针

快慢指针的灵感可以从一个生活化的问题想：

```text
如果两个人在一条没有终点的环形跑道上跑，一个人快，一个人慢，他们迟早会相遇。
```

链表如果有环，就像一条路最后接回了前面，变成了环形跑道。

这时让两个指针从头节点出发：

- 慢指针每次走一步。
- 快指针每次走两步。

如果链表没有环，快指针会先走到空节点。

如果链表有环，快指针进入环后会一直在环里跑。慢指针也会进入环。因为快指针每轮都会比慢指针多走一步，所以它们之间的距离会不断缩小，最后一定会相遇。

## 核心理解

快慢指针不是靠记住走过的节点来判断有没有环，而是利用了“速度差”。

可以这样记：

```text
有环：快指针追上慢指针。
无环：快指针走到 None。
```

快慢指针把“有没有重复走到某个节点”这个问题，转换成了：

```text
两个速度不同的指针会不会相遇。
```

## 和哈希表的区别

哈希表方法：

- 思路直观。
- 记录所有走过的节点。
- 空间复杂度是 `O(n)`。

快慢指针方法：

- 不需要额外集合。
- 只用两个指针。
- 空间复杂度是 `O(1)`。

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 复盘

- 判断环的第一反应可以是集合，因为“环”意味着节点会重复出现。
- 想优化空间时，可以考虑快慢指针。
- 只要题目里出现“链表是否有环”“是否会重复绕回去”，就可以联想到快慢指针。
- 快慢指针的本质是利用速度差：快的指针如果一直跑不出去，就一定会追上慢的指针。
